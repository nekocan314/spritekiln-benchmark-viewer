## 1. 試した構成・設定（入力）

### 1.1 `spritekiln.toml` に固定したプロジェクト共通スタイル
全アセットで `camera.pitch`・`camera.scale`・光源・ルック設定をロックした。

| 項目 | 採用値 | 選定理由 |
|---|---|---|
| `view` / `directions` / `mirror` | `topdown` (pitch 38°) / `8` / `false` | 武器左右非対称（右手剣・左手盾）と一貫光源を維持するためミラー不使用 |
| `size` / `camera.scale` / `camera.center` | `64` / `0.04` / `[0, 1.04, 0]` | 1px = 0.04 world units。組み込みキット前提（最小厚み 0.04）と一致させつつ、兜クレストや魔法帽子の上端余白 ≥2px を確保 |
| `proportions` / `face` | `stylized` (`head.scale: 1.36`) / `minimal` | 2.8頭身（全高約42〜46px）。2px未満の鼻・口・耳突起を廃し、1×2pxの暗色瞳のみで視認性を確保 |
| `palette` | `fantasy_rpg`（自作共通パレット） | 4〜6段の色相シフト陰影（16ランプ＋VFX3種）。隣接部位は色相より明度差で分離（銀鋼 vs 濃紺インナー、金髪 vs 緑チュニック・赤マント・紫帽子） |
| `outline` / `shading` / `lines` | `selective` / `soft` / `depth` | 選択的輪郭＋全段ソフト陰影＋パーツ間深度線（金属のみ個別 `crease: true, edge_highlight: true` を付与し顔や布へのノイズ波及を防止） |
| `highlights` / `dither` / `light` | `true` / `none` / `classic` | 金属ハイライト有効、ディザ無しでドット面を明瞭化、左上基準の王道クラシック光 |
| `animation` / `snap` | `fluid` / `true` | `root`・`torso_rot` を整数ピクセルへスナップし、待機モーションの boiling を抑止 |

### 1.2 継承設計（`extends` / `use`）と共通アクション連動アーキテクチャ
```text
built-in humanoid
  └─ art/specs/templates/base_humanoid.yaml  (368行: 2.8頭身素体・共通パレット・共通4クリップ・汎用揺れチャンネル)
       ├─ art/specs/kits/hair_{short,ponytail,long}.yaml         (独立髪型キット 3種)
       ├─ art/specs/kits/outfit_{light,heavy,robe}.yaml          (独立衣装キット 3種)
       ├─ art/specs/kits/weapon_{sword_shield,staff}.yaml        (独立武器キット 2種)
       └─ art/specs/characters/preset_{a..e}/preset_*.yaml       (32〜56行の差分YAMLのみ; 素体無改変)
```
- **共通アクション連動の要（`host_channels:` パターン）**：
  - `base_humanoid.yaml` に汎用セカンダリチャンネル（`cloth_sway`, `hair_swing`, `hair_sway`, `weapon_pitch`, `weapon_roll`, `shield_guard`）を定義。
  - 各キットが `host_channels:` 経由でこれらを読み取ることで、**キットを装備していないプリセットでも未定義チャンネルエラーを出さず、装備中のプリセットだけが自動的にマント・ポニーテール・ロングヘア・武器角度を連動させる**構造を実現した。
- **複数ボーン横断キット**：衣装・武器キットは単一 `at:` に縛られず、`outfit_heavy` は `pelvis`・`shoulder_L`（自動 `_R` ミラー）・`head`、`weapon_sword_shield` は `wrist_R`・`wrist_L` へ直接パーツを接続した。

### 1.3 兜・帽子と髪型の干渉処理ルール（検証結果）
1. **フルカバー兜（`outfit_heavy` + `hair_ponytail` の実証テスト）**：
   - 無対策で同時装着すると、背面・側面（`se`, `e`, `n`）でポニーテールとリボンが鋼鉄ドームおよび深紅クレストを貫通することを `pose --focus head` で確認。
   - **確定ルール（排他方式）**：フルカバー兜装備プリセット（Preset C）では髪キットを `use:` せず（`HEAD_FULL_COVER` 排他）、さらに頬当てで斜め向きの目が隠れる仕様に合わせて `remove: [review.keep.eyes]` を明示指定した。
2. **つば広帽子（`outfit_robe` + `hair_long`）**：
   - **確定ルール（パラメータ圧縮方式）**：`hair_long` に頭頂ボリューム係数 `volume` を設け、帽子併用時のみ `with: {volume: 0.72}` を指定。頭頂は帽子内に収めつつ、サイドロックと背中ロング毛束だけを貫通ゼロで綺麗に露出させた。

### 2.3 見た目・アクションの自然さの評価

- **うまく機能した点（強み・上限の高さ）**：
  1. **8方向の造形・ライティング一貫性**：手描きドット絵で最も破綻しやすい斜め（`se/ne/nw/sw`）や背面（`n`）の立体整合・光源統一・選択的輪郭が、2.8頭身64px級で商業インディー水準に到達した。
  2. **質感分離と動的ライティング耐性**：金属（`finish: metal, crease: true, edge_highlight: true`）・布（`matte`）・発光クリスタル（`emissive: true, glow`）の分離が明瞭で、自動出力される法線マップ＋発光マップをビューア上の簡易点光源シェーダーで照らすと、立体感とクリスタルの発光が破綻なく映える。
  3. **アクションのキレとセカンダリ揺れ**：`attack` の 50ms 補間なしヒットフレーム＋`arc` スマア＋`squash: 1.07`、`dodge` の沈み込み→前傾ステップ→着地ブレーキにおいて、ポニーテールや肩マント・ローブ裾が位相遅れで自動連動し、非常に気持ち良い手触りが出た。`idle` の `boil` も平均 0.029〜0.046 と極めて静粛。
  4. **AI自律QAループの実用性**：人間が目で気付きにくい「`attack/e/2` の1px端クリップ」「兜キャラへの `review.keep.eyes` 誤継承」「`nw` 方向の剣消失」を `qa.json` と `pose --changes` が決定論的に指摘し、1〜2回の部分編集で修正完了できた。

- **限界が見えた点**：
  1. **64px での大型装飾×武器の同時視認性限界**：Preset D のように「つば広魔法帽子＋ロングヘア＋長い杖」が重なると、`w`/`nw` 方向でつばの裏に杖のシャフトやクリスタルが一時的に隠れやすい（静止・歩行・攻撃のすべてで完全露出させるのは物理的に狭く、武器ごとに専用モーションまたはより強いチートが必要）。
  2. **武器種を跨ぐ共通 `attack` モーションの表現上限**：共通モーションで剣盾と杖の両方を破綻なく動かすことはできたが、剣は横斬り・杖は魔法詠唱突き上げのように武器種ごとの「らしさ」を最大化するなら、攻撃クリップだけは武器種別ミックスイン（`attack_sword` / `attack_staff`）へ分けるのが本筋。
  3. **細部造形（顔表情・指先・紋章の細密柄）**：64px・`scale: 0.04` では 2px（0.08 world units）未満のディテールは潰れる／チラつくため、表情差分や細かい装飾は割り切る必要がある。

## 3. 踏んだ罠と回避策（再現性のある知見）

1. **肌マテリアルのプラスチック状ハイライト**
   - **事象**：`skin` に `finish: soft` を設定したところ、額や頭頂に白い十字型のスペキュラハイライトが出て不自然になった。
   - **原因**：`finish: soft` は広めのハイライトを有効化し、ランプ最明色を強制適用する仕様（組み込み `humanoid` は `skin` に `finish` を付けていない）。
   - **回避策**：`skin` には `finish` を付けず `{ramp: skin, gamma: 0.75}` とし、肌ランプ最明色も白飛びしない暖色（`#f5d4b2`）に抑える。

2. **プロジェクト外ディレクトリ（`/tmp/`）でのカスタムキット解決失敗**
   - **事象**：干渉検証用の仮スペックを `/tmp/` に置いて `spritekiln pose` を実行したところ、`kit "hair_ponytail" not found` で失敗した。
   - **原因**：SpriteKiln はスペックの親ディレクトリを辿って `spritekiln.toml` を探し、`art/specs/kits/` を解決するため。
   - **回避策**：一時検証スペックであっても必ず `spritekiln.toml` 配下に作成し、検証後に削除する。

3. **右手武器（`wrist_R`）の方向別チート符号逆転による背面消失**
   - **事象**：`weapon_sword_shield` の背面 `n` / `nw` で剣が胴体の裏に完全に隠れて消えた。
   - **原因**：キャラ右手（`-x` 側）で `+y` 方向に伸びる刃を外側へ開く Z軸回転は `+rz` だが、`-rz` を指定していたため胴体側へ倒れていた。また `nw`（yaw=-135）では手首自体が奥側にあるため回転だけでは隠れやすかった。
   - **回避策**：`n` / `nw` 方向では `+rz` で外側へ開きつつ、わずかな外側 `pos` チート（`-0.10*cheat*pulse(yaw, -135, 45)`）を組み合わせて全8方向可視化を達成した。

4. **静止時チートとアクションチャンネルの合算による左右端クリッピング**
   - **事象**：杖（`weapon_staff`）の `attack/e/2` と `attack/w/2` で、杖長を短くしてもなお左右端（`x=0`, `x=64`）で1pxクリッピングが発生した。
   - **原因**：静止・歩行時の視認性を上げるための `e`/`w` 方向ピッチチート（`+0.45*pulse(yaw, ±90, ...)`）が、攻撃ヒット時の `weapon_pitch` と合算され、真横方向だけ杖が完全に水平超過していた。
   - **回避策**：方向別チート項に `(1 - clamp(abs(weapon_pitch), 0, 1))` を乗算してアクション中は自動減衰させることで、静止・歩行の視認性と攻撃時の枠内収まり（クリッピング0件）を両立した。

5. **共通素体 `review.keep` の不要継承による誤警告**
   - **事象**：兜装備の Preset C で `review.keep.eyes` が10件以上の警告を出した。
   - **原因**：`extends: base_humanoid.yaml` は `review.keep` も深マージするため、兜の頬当てで3/4方向の目が隠れる仕様と衝突した。
   - **回避策**：兜プリセット側で `remove: [review.keep.eyes]` を明示し、兜固有の `helm_crest` / `helmet` のみを監視対象とした。

6. **背の高い頭部装飾＋上方向ステップによる上端クリッピング**
   - **事象**：魔法使い帽子（Preset D）と騎士クレスト（Preset C）で、`idle/s` や `dodge/n` において上端クリッピングが発生した。
   - **原因**：`camera.center.y = 0.92` のままだと頭上余白が不足し、さらに北方向（`n`/`ne`）への `root.z` 前進が画面上方向移動になるため。
   - **回避策**：ゲーム共通定数である `camera.scale` / `pitch` は一切変えず、`camera.center` を `[0, 1.04, 0]` へ調整（足元余白を活かしつつ上端+3px確保）し、帽子先端と `dodge` ステップ距離を微調整してクリッピング0件を達成した。

## 4. 共通化・Skill昇格の判定

- **区分**：**`共通技術としてSkill昇格候補`**
- **昇格するならルール1行要約**：
  > 「SpriteKilnでは `base_humanoid` に汎用セカンダリチャンネル（`cloth_sway`/`hair_swing`/`weapon_pitch`）を集約してキット側から `host_channels:` 参照し、武器の方向別チートは `(1 - clamp(abs(weapon_pitch), 0, 1))` でアクション時減衰・フルカバー兜は髪キット排他＋`remove: [review.keep.eyes]` とし、`validate → pose --changes → pose --focus head → arcs → render/review` の決定論的ゲートを通す。」

### 多キャラ・大量着せ替え企画（例：星界のような企画）へ展開する際の課題と現実的な運用ラインへの所感

1. **組合せ爆発と事前ベイク型の現実解**：
   - SpriteKiln は3D SDFのレイマーチング結果を1枚の2Dアトラスへ事前ベイクする方式であり、1体（4クリップ×8方向＝200フレーム）の生成に `numba` ありでも約90〜120秒を要する。
   - したがって、**「髪10種 × 衣装20種 × 武器10種 ＝ 2,000通り」をランタイム着せ替え用に全通り事前ベイクするのは容量・ビルド時間の両面で非現実的**。
   - 一方、**「固有キャラ（プレイアブル20〜50体・NPC・敵種別）やジョブ／スキン単位の完成プリセット（数十〜百体規模）」を共通素体＋キット合成で量産するパイプライン**としては圧倒的に優秀（1体追加＝35行の差分YAML＋2分ビルド、画風・頭身・光源・法線・発光・足滑り速度 `ground_speed` が全キャラ自動統一される）。

2. **もしランタイム自由着せ替え（紙人形・レイヤー合成）を狙う場合の壁と対策**：
   - パーツ単体だけを透明背景で個別レンダリングして2Dエンジン側で重ねる方式は、**Zオーダー逆転（背面 `n` でマントが胴の前・武器が裏になる、腕が胴の前を横切る）と、パーツ間のセルフシャドウ／選択的輪郭／深度内線の破綻**が起きやすい。
   - 現実的な運用ラインは以下の2択：
     - **推奨案A（プリセット／ジョブ単位ベイク）**：髪色・衣装色はシェーダーのパレットスワップ（インデックスカラー化 or ランプ置換）でランタイム無限対応し、シルエットが変わる「ジョブ衣装・固定キャラ・主要装備セット」だけを SpriteKiln の `extends`/`use` で量産ベイクする。
     - **推奨案B（武器のみソケット分離）**：本体（素体＋髪＋衣装）を SpriteKiln でベイクし、武器だけ `sockets`（`hand_R` の `[x, y, depth]`）を使ってエンジン側で差し替え描画する。これで「キャラ数 × 武器数」の乗算爆発を完全に断ち切れる。

3. **量産に向けた追加の運用規格（Skill化時に組み込むべき点）**：
   - キットにメタ規約として **頭部干渉クラス**（`NONE` / `HAT_LOW_VOLUME` / `HELM_FULL_COVER`）を定め、プリセット生成時に自動で `volume` 圧縮または髪キット除外＋`review.keep.eyes` 除外を適用する。
   - 共通モーション（`idle`, `walk`, `dodge`, `hit`, `death`）は `base_humanoid` で完全共有し、攻撃モーションのみ武器カテゴリ別テンプレート（`anim_sword.yaml`, `anim_staff.yaml`, `anim_bow.yaml`）に分離すると、量産効率とアクション品質の両方を最大化できる。
